## What held

- **Companion countdown**: the setting renders with its value, the readout
  explains it, and the co-pilot's proactive chip ("Codebase indexieren")
  appears on a workspace that has no index — the behaviour ordered in Block 1.4.
- **Long session**: eight turns, one session, no layout break; turn heads,
  replay rows and copy/speak/regenerate actions each render once per turn.
- **Capability matrix** reads the guard: nine tools, the main agent writes.
- **Mobile 390 px**: the action bar stays on one line.

## What should change (measured, not guessed)

1. **Context meter reads "0 %"** at 955 of 1,048,576 tokens. True, and useless:
   below one percent it should print `<1 %`.
2. **The "Aufgaben" panel opens over the answer column.** In the long session it
   covers the assistant's last paragraph. It belongs beside the reading column,
   not on top of it, or it should start collapsed after the first turn.
3. **The agents import is invisible in the browser** with no hint why. A row
   that says "Import nur in der Desktop-App" would say what the absence means.
4. **The countdown is a number field with a range hint**, not the slider the
   order asked for. The live readout exists; the control shape does not.
5. **The status bar's right cluster truncates** ("5 A…", "0,17") at 1440 px once
   five chips are present.

None of these is a release blocker: the release assets were cut from the tag
that carries the behaviour above, and the list above is what the next wave
starts from.
