# The workspace context contract

Ephe reads the workspace's own instruction files before the first turn. One resolver,
`core/workspace_rules.py`, owns the file list, the caps, the status of every file and
the text the model receives. `GET /api/context/stages` reports the same answer, so the
prompt and the surface cannot drift. `core.workspace_rules.explain_workspace_context()`
is the machine-readable form for the UI and the CLI.

## Layers and precedence

Later layers are injected later: they sit closer to the conversation and read as the
more specific voice.

| Order | Layer | File | Alias | Per-file cap | Scope |
|---|---|---|---|---|---|
| 1 | `agents` | `AGENTS.md` | — | 6,000 | workspace |
| 2 | `rules` | `.ephe/rules/*.md` | — | 6,000 (12,000 combined) | workspace |
| 3 | `soul` | `SOUL.md` | `.ephe/persona.md` | 6,000 | workspace |
| 4 | `user` | `USER.md` | `.ephe/user.md` | 4,000 | workspace |
| 5 | `memory` | `MEMORY.md` | — | 6,000 | private |

The first file of an alias pair wins and the other one is ignored. Rule files are
sorted by file name and read one directory deep.

`IDENTITY.md` is not a layer. The identity block is generated by the harness and
carries the product name, the model disclosure and the local/offline statement. A
workspace `IDENTITY.md` is ignored; personality, tone and boundaries belong in
`SOUL.md`.

## Caps

All layers share `WORKSPACE_CONTEXT_MAX = 28,000` characters. The layer budgets are
12,000 for the rules group (`AGENTS.md` plus `.ephe/rules/`), 6,000 for `SOUL.md`,
4,000 for `USER.md` and 6,000 for `MEMORY.md`; together they equal that number.
Provenance headers and separators are paid out of it, so the assembled text never
exceeds the total. A file over its own cap is cut with a truncation marker inside the
cap. When the total is exhausted, the remaining layer is reported as `skipped` with
reason `no-budget` instead of vanishing.

## Status words

| Status | Meaning |
|---|---|
| `included` | Read whole and injected. |
| `truncated` | Read, cut to a cap, marker in the text. |
| `empty` | Read, contained no non-whitespace text. |
| `unreadable` | The read failed (permissions, decoding, I/O). |
| `denied` | Refused before reading; reason `protected-root` or `outside-root`. |
| `skipped` | Deliberately left out; reason `path-filter`, `shared-context` or `no-budget`. |

An absent file is not a layer and produces no row. The report names what the reader
found; it does not invent rows for files that were never there.

## `paths:` frontmatter

A rule file may declare where it applies:

```markdown
---
paths:
  - "src/**/*.ts"
  - "docs/**/*.md"
---
Run the TypeScript build before claiming a change is green.
```

The frontmatter is removed before injection. A file without frontmatter loads on
every turn. A file with `paths:` loads only when one of the globs matches a path in
the turn's workspace context; a mismatch is reported as `skipped` with reason
`path-filter`. `*` stays inside one path segment and `**` crosses segments, so
`src/**/*.ts` matches `src/app.ts` and `src/lib/a.ts`, while `*.ts` matches only the
workspace root.

`read_workspace_rules(paths=...)` receives that turn context. Called without the
argument it behaves as before and does not filter. An explicit empty list means "no
paths in this turn": unscoped rules still load, path-scoped rules stay out. A
malformed `paths` value degrades to no filter, because a broken filter must not
silently drop the user's own instructions. Absolute paths outside the workspace
cannot match and are ignored.

## Private memory

`MEMORY.md` carries curated long-term notes and no conversation transcript. It loads
in the private main context and stays out of a shared session
(`read_workspace_rules(shared=True)`), where it is reported as `skipped` with reason
`shared-context`. That check runs before the file is read.

## Portability

`AGENTS.md` is the portable project contract. A workspace that carries only that file
works exactly as before; `SOUL.md`, `USER.md`, `MEMORY.md` and `.ephe/rules/` are
optional overlays. Copying a repository between Ephe and another agent keeps
`AGENTS.md` intact.

The overlay idea comes from the wider ecosystem, with Ephe's own caps and report:

- Claude Code keeps project memory in `CLAUDE.md` and supports path-scoped rule files
  with `paths:` frontmatter; Ephe adopts the frontmatter for `.ephe/rules/` and keeps
  `AGENTS.md` as the canonical filename.
- OpenClaw splits workspace context into persona (`SOUL.md`), stable user preferences
  (`USER.md`, 4,000 characters) and curated memory (`MEMORY.md`); Ephe adopts that
  split verbatim and caps each layer.
- Other agent runtimes carry a curated memory file as long-term context; Ephe reads
  `MEMORY.md` as an overlay instead of growing a second store.
- Pi reads `AGENTS.md` as its project contract; Ephe keeps that standard and adds the
  optional layers beside it.

Ephe is deliberately different in one respect: every layer passes through one
resolver that reports provenance, size and status for each file. A refused, empty or
filtered file is named with a stable reason, and the total cap is visible in the same
answer. The workspace files are read-only context; the agent does not rewrite them,
and the generated identity block stays outside the user's editable layers.
