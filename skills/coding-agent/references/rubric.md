# Quality Rubric

1. Read before you edit. Never guess file content.
2. Keep changes minimal and focused on the task; do not reformat unrelated code.
3. Every edit must be justified by the task; no drive-by refactors.
4. Run tests after each change; if they fail, fix and re-run until green or you can prove the failure is pre-existing.
5. Report honestly: changed files, test results, and anything you could not do.
6. Ground every number/path on real tool output; no simulated output without a returned path.
